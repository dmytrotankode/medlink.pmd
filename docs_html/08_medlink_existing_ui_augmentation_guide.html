extension 8. Посібник безшовного доповнення існуючих форм та процесів МІС «Медлінк»

Інструкція для розробника та системного аналітика: як інтегрувати функціонал ПМГ-2026 виключно шляхом точкових адитивних розширень поточних форм, меню та сервісів проєкту evomis, не порушуючи їх стабільність.

🎯 Головний інженерний принцип: Ми не створюємо ізольовану окрему систему і не ламаємо жодного існуючого компонента. Всі зміни впроваджуються як доповнення (augmentations / extension hooks) до існуючих файлів репозиторію МІС «Медлінк» (evomis): у картку взаємодії додається пре-білінг віджет, у навігаційне меню — пункт аналітики, а в процесор OpenXML — новий клас NszuStatementXlsxProcessor на базі існуючого CoreXlsxProcessor.

Лікар (стаціонар / амбулаторія) Вносить ЕМЗ у Details.vue, обирає діагноз та послугу, натискає «Підписати КЕП». Про помилку дізнається лише через місяць після відмови НСЗУ. Вносить ЕМЗ як звичайно. Система миттєво рахує очікуваний тариф та валідує посаду лікаря ($P157$). Якщо є ризик дефектури — видає підказку до підписання. Кнопка «Підписати КЕП» залишається активною. Перевірка працює як інформаційний асистент, не блокуючи невідкладну реєстрацію пацієнта.
Економіст / Моніторинг Вручну відкриває Excel-файл НСЗУ на 50 МБ у Microsoft Excel, фільтрує помилки, вручну розраховує тарифи за формулами. Завантажує файл у веб-інтерфейс через OpenXML. Система автоматично проводить 2-Way звірку з базою mis_encounter та виявляє приховану дефектуру. Використовується існуючий стек Quasar 1.15.3 та потоковий SAX-парсер, що виключає падіння сервера за пам'яттю.

Відкриває вкладку «Звіт по лікарях», бачить нарахований дохід за кожним лікарем, суму втраченої дефектури та статус ургентних випадків Пакета 9. Агрегація спирається на реальні сутності org_employee та org_department, без створення дублюючих структур.
